# Review 2026-11: Graph layer compared with MailCraft

A review of this resource against [MailCraft](https://github.com/UCS-Care-Group/mailcraft)
(a Rust mail client with a carefully engineered Microsoft Graph layer, `crates/net/src/graph*`)
and against the lessons from `mcp-outlook365`. MailCraft served as a reference, not as an
authority: every finding below was traced in this code base.

**Status:** `open`, `fixed` (commit on branch `review-fixes`), `wontfix` (with reason).
**Confidence:** *confirmed* = the code path was read end to end; *plausible* = the code is as
described, but the server's reaction was not verified.

## Critical: data loss or unwanted mail

| # | Finding | Where | Confidence | Status |
|---|---------|-------|------------|--------|
| C1 | **Every event edit replaces the server body.** An HTML body (almost every event, every Teams meeting) is read as `bodyPreview` (~255 chars, plain text); every PATCH sends the full `toJson()` with that text as `body`. Changing only the category of a Teams meeting loses the join link and the agenda. | `calendar/grapheventhandler.cpp` `toEvent` (body), `toJson`; `graphresource.cpp` event PATCH | confirmed | fixed |
| C2 | **Recurrence exceptions are not modelled.** The delta `$select` lacks `type`, `seriesMasterId`, `originalStart`; moved/cancelled occurrences show at their original time. Editing one occurrence locally (RECURRENCE-ID) POSTs a standalone event (duplicate); EXDATEs are never written, so "delete this occurrence" never reaches the server. MailCraft finds the occurrence through `/events/{id}/instances` and changes it there. | `jobs/graphfetchpimitemsjob.cpp` (`$select`), `grapheventhandler.cpp` (recurrence), `graphresource.cpp` `itemAdded` | confirmed | fixed (writing occurrences: built, wants a check in KOrganizer) |
| C3 | **Moving a meeting to another calendar cancels it for all attendees.** The move recreates the event (without attendees) and DELETEs the original; for an organizer's meeting Exchange sends a cancellation to everybody. The comment assumes no mail goes out. | `graphresource.cpp` `itemsMoved` → `movePimItem` | confirmed (code), Graph DELETE semantics documented | fixed |
| C4 | **`showAs` collapses to free/busy.** tentative/oof/workingElsewhere are read as busy and every PATCH writes `busy`: editing an out-of-office block turns it into busy. | `grapheventhandler.cpp` `toEvent`/`toJson` | confirmed | fixed |
| C5 | **Mail flag "complete" is lost.** Every read/unread change also PATCHes `flag.flagStatus` from the local Flagged flag; a completed flag becomes `notFlagged` (and the follow-up dates are likely dropped with the replaced complex value). | `mail/graphmailhandler.cpp` `flagPatchBody`, `jobs/graphfetchitemsjob.cpp` | confirmed (complete), plausible (dates) | fixed |
| C6 | **Events, contacts and tasks keep ghosts after a delta reset.** A full re-listing (expired delta token, mapping-version bump, cleared sync state) is delivered as incremental, so items deleted on the server while the token was dead stay locally forever. Mail does it right (`isFullListing` → `syncItemsFull`). | `graphresource.cpp` `fetchPimItemsJobFinished`, `jobs/graphfetchpimitemsjob.*` | confirmed | fixed |
| C7 | **A malformed 200 answer counts as success.** Invalid JSON becomes `{}`: a full listing then syncs an empty folder (local items deleted), a create commits an empty remote id. MailCraft fails hard (`graph.rs` `page_from`). | `graphclient/graphrequest.cpp` reply handling | confirmed | fixed |

## Important

| # | Finding | Where | Confidence | Status |
|---|---------|-------|------------|--------|
| I1 | **POST is retried on 503**, `/send` included (`failureForStatus` treats 503 as `NotExecuted`; the internal 429/503 loop ignores the method). If `/send` went through despite the 503 and the retry then fails for good, the code deletes the "draft", which with immutable ids is the Sent Items copy, and reports an error that invites a second send. MailCraft never repeats a non-idempotent request by itself (`pace.rs` `Kind::Once`). | `graphrequest.cpp` retry + `failureForStatus`, `graphbatchjob.cpp`, `graphresource.cpp` `sendMessage` | confirmed (code path) | fixed |
| I2 | **`@odata.nextLink` is followed to any host with the bearer token**, and there is no page cap: a `nextLink` pointing at the same page loops forever. Stored delta links live in a collection attribute that any local Akonadi client can rewrite. Qt's default redirect policy may follow cross-host https redirects. | `graphrequest.cpp` paging | confirmed (redirects: plausible) | fixed |
| I3 | **Moving a To Do task loses its checklist items, linked resources and attachments** (recreate + delete without copying sub-resources). | `graphresource.cpp` `movePimItem` | confirmed | fixed |
| I4 | **Clearing a field never reaches the server.** Removing due/start date, location, categories or description sends nothing, so the server keeps the old value. To Do `waitingOnOthers`/`deferred` are written back as `notStarted`. MailCraft sends `null` to clear (`tasks.rs`). | `todo/graphtodohandler.cpp`, `grapheventhandler.cpp` `toJson` | confirmed | fixed |
| I5 | **Contact round-trip loses data:** e-mail display names are dropped on read and the whole `emailAddresses` array is rewritten; fax/pager/other phones become business phones, only one mobile survives; deleting an address locally never clears it on the server. | `contact/graphcontacthandler.cpp` | confirmed | fixed (clearing an address or the mobile only when the server had one) |
| I6 | **No concurrency limit per mailbox.** The cache-miss path of `retrieveItems` starts one request per item at once (Graph allows 4 concurrent requests per mailbox), causing a 429 storm; failed items are silently dropped. A 429 does not pause the other requests. MailCraft: `pace.rs` gate (4 at once, 2 background). | `graphresource.cpp` `retrieveItems` | confirmed | fixed for the one fan-out (cache-miss re-fetch); no client-wide gate yet |
| I7 | **`Retry-After` is parsed as seconds only**; the HTTP-date form becomes 0 and falls back to a 1–16 s backoff. The retry counter is not reset per page, so a long paged delta has 5 retries in total. | `graphrequest.cpp`, `graphbatchjob.cpp` | confirmed | fixed |
| I8 | **The folder delta treats only 410 as an expired state**; a 400 `ErrorInvalidSyncStateData` fails every tree sync until the state is cleared by hand. No job recognises `syncStateNotFound`/`resyncRequired`. | `jobs/graphfetchfoldersjob.cpp`, item delta jobs | confirmed | fixed |
| I9 | **Large mail fails with a raw HTTP error.** Send, draft save and Fcc upload POST base64 MIME to `/me/messages`; Graph caps that request at about 4 MB, so a mail with a 3.5 MB attachment cannot be sent or saved. MailCraft builds drafts as JSON plus attachments, through upload sessions above 3 MB. | `graphresource.cpp` `sendMessage`, draft save, `uploadMailItem` | confirmed (no handling), plausible (exact limit) | wontfix: live-checked 2026-11-20, POST /me/messages took MIME of 3.4, 4.7, 8.1, 20.3 and 37.8 MB (requests up to 50 MB); the limit is the mailbox's send size, whose error Graph words itself |
| I10 | **No refresh-and-retry on a 401 in the middle of a run**; only the poll timer checks the token. | `graphrequest.cpp` | confirmed | deferred: a 401 holds a change back and re-sends it after a silent sign-in (retryLater, mReauthenticate); a sync re-runs at the next poll. Only a delay; a refresh inside GraphRequest needs a GraphOAuth signal for later renewals |
| I11 | **Payload and photo batches bypass `GraphBatchJob`**: one 404 or 429 sub-response fails the retrieval of all 20 messages; a throttled photo is silently skipped. | `jobs/graphfetchitempayloadjob.cpp`, `graphfetchpimitemsjob.cpp` | confirmed | fixed |

## Already done well

`transactionId` on event create and move; Windows/IANA zone mapping with fallbacks and
`originalStartTimeZone`; correct all-day exclusive/inclusive end; the delta link is stored only
after a successful `ItemSync` commit; per-sub-request immutable-id header and 20-request chunks
in `GraphBatchJob`; the `NotExecuted`/`Uncertain` failure classes and `GraphRetryPolicy`;
500/502/504 not repeated; drafts replaced create-before-delete; Fcc copies matched by
`internetMessageId`; To Do recurrence placeholders tolerated.
